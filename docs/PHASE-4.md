# Phase 4: न्यूज़ CMS, आर्टिकल एडिटर, संपादकीय वर्कफ़्लो, असाइनमेंट डेस्क, वर्ज़न हिस्ट्री

## 1. लक्ष्य

- **ख़बर (§7)**: शीर्षक, उप-शीर्षक, सार, पूरा लेख (रिच एडिटर), मुख्य इमेज + कैप्शन/क्रेडिट, गैलरी, वीडियो, ऑडियो, श्रेणी/उप-श्रेणी, टॉपिक, टैग, लोकेशन (देश से मोहल्ले तक; सबसे नीचे वाला स्तर चुनें, ऊपर के स्तर अपने आप), रिपोर्टर, संपादक, स्रोत, न्यूज़ क्रेडिट, प्रकाशन/शेड्यूल समय, फ़्लैग (ब्रेकिंग, फ़ीचर्ड, ट्रेंडिंग, एडिटर पिक, एक्सक्लूसिव, लाइव, प्रायोजित), संबंधित ख़बरें, SEO।
- **काम**: बनाना, बदलना, प्रीव्यू, कॉपी, बंद/चालू, ट्रैश, वापस, स्थायी रूप से हटाना, बल्क, CSV एक्सपोर्ट।
- **वर्कफ़्लो (§8)**: ड्राफ़्ट → भेजी गई → डेस्क समीक्षा → फ़ैक्ट चेक → मंज़ूर → शेड्यूल/प्रकाशित → अपडेट/सुधार → आर्काइव। अस्वीकार पर कारण ज़रूरी; रिपोर्टर को कारण दिखता है। संपादकों की आंतरिक टिप्पणियाँ (रिपोर्टर को नहीं दिखतीं)। किसी रिपोर्टर को "सीधे प्रकाशन" = उस यूज़र को `news.publish` (यूज़र-स्तर अनुमति)।
- **शेड्यूल**: shared hosting पर cron ज़रूरी नहीं। हर अनुरोध पर (हर मिनट में अधिकतम एक बार) समय आ चुकी ख़बरें अपने आप प्रकाशित।
- **वर्ज़न हिस्ट्री (§33)**: हर सेव पर पूरा स्नैपशॉट; किसने, कब, क्यों। प्रकाशित ख़बर बदलने पर कारण ज़रूरी; चाहें तो "सार्वजनिक सुधार सूचना"। दो वर्ज़न की तुलना (diff), पुराना वर्ज़न वापस लाना।
- **असाइनमेंट डेस्क (§9)**: शीर्षक, विवरण, रिपोर्टर, बीट (श्रेणी), लोकेशन, प्राथमिकता, डेडलाइन, निर्देश, अटैचमेंट, स्थिति। रिपोर्टर के लिए टैब: आज / आगे / देर हो चुकी / पूरे। "लिखना शुरू करें" से असाइनमेंट से जुड़ी ड्राफ़्ट ख़बर; ख़बर भेजने/प्रकाशित होने पर असाइनमेंट की स्थिति अपने आप।
- **डैशबोर्ड**: आज की ख़बरें, मंज़ूरी बाकी, ड्राफ़्ट, शेड्यूल, मेरे असाइनमेंट।
- **होमपेज बिल्डर**: "हाथ से चुनी ख़बरें" में अब ख़बर खोजकर चुनने का बॉक्स।

## 2. डेटाबेस (migration `000004`)

| टेबल | मुख्य कॉलम |

| `news` | title, subtitle, slug (unique), summary, content, featured_image, image_caption, image_credit, video_url, audio_file, category_id, location_id, reporter_id, editor_id, assignment_id, source, news_credit, status, 7 फ़्लैग, published_at, scheduled_at, correction_note, meta_title/description/keywords, canonical_url, robots, views, word_count, language_id, created_by, updated_by, timestamps, deleted_at |

## 3. रूट (एडमिन)

| पता | काम | अनुमति |

| /admin/news (+create, {id}/edit, preview, duplicate, trash, restore, DELETE, bulk, export) | ख़बरें | news.view/create/edit/delete/export |
| POST /admin/news/{id}/transition | भेजें, समीक्षा, फ़ैक्ट चेक, मंज़ूर, अस्वीकार, प्रकाशित, शेड्यूल, बंद, आर्काइव | वर्कफ़्लो नियम (नीचे) |

| /admin/news/{id}/history, revisions/{rid}, POST revisions/{rid}/restore | हिस्ट्री, तुलना, वापस लाना | news.edit |
| /admin/news/search (JSON) | संबंधित/होमपेज के लिए खोज | news.view |
| /admin/assignments (+create, edit, status, start, DELETE) | असाइनमेंट | assignments.* |

## 4. कोड

- **Controllers**: `Admin\NewsController` (CRUD, बल्क, एक्सपोर्ट), `Admin\NewsWorkflowController` (स्थिति, टिप्पणी, हिस्ट्री, वर्ज़न), `Admin\AssignmentController`
- **Models**: `News`, `NewsRevision`, `NewsRemark`, `Assignment`
- **Services**: `NewsWorkflow` (स्थितियाँ, बदलाव के नियम), `NewsService` (सेव + रिश्ते + वर्ज़न + शेड्यूलर + पहुँच), `TextDiff`
- **Repositories**: `NewsRepository`, `AssignmentRepository`
- **Validators**: `NewsValidator`
- **Middleware**: `SchedulerMiddleware` (शेड्यूल की गई ख़बरें)

## 5. अनुमतियाँ

| अनुमति | क्या मिलता है |
|---|---|
| news.view | सूची; बिना `news.approve` सिर्फ़ अपनी ख़बरें |
| news.create / news.edit | ख़बर लिखना; अपनी ख़बर सिर्फ़ ड्राफ़्ट/अस्वीकार स्थिति में बदल सकते हैं |
| news.approve | डेस्क: सभी ख़बरें देखना/बदलना, समीक्षा, फ़ैक्ट चेक, मंज़ूर, अस्वीकार, आंतरिक टिप्पणी, फ़्लैग |
| news.publish | प्रकाशित, शेड्यूल, बंद, आर्काइव (रिपोर्टर को देने पर "सीधे प्रकाशन") |
| news.delete | ट्रैश/वापस, ट्रैश से स्थायी रूप से हटाना |
| news.export | CSV |
| news.manage | किसी भी स्थिति की कोई भी ख़बर बदलना, पुराना वर्ज़न वापस लाना |
| assignments.view | अपने असाइनमेंट (manage के साथ सभी) |
| assignments.create/edit/delete/manage | असाइनमेंट देना और संभालना |

## 6. सुरक्षा

| जोखिम | बचाव |
|---|---|
| लेख में XSS | सर्वर पर allowlist sanitizer (Phase 2), वीडियो सिर्फ़ YouTube/लाइब्रेरी |
| दूसरे रिपोर्टर की ख़बर देखना/बदलना (IDOR) | हर ID पर पहुँच जाँच (`NewsService::canView/canEdit`), सूची में भी फ़िल्टर |
| बिना अनुमति प्रकाशन | स्थिति बदलने का हर रास्ता `NewsWorkflow` से; फ़ॉर्म से `status` नहीं आता; फ़्लैग सिर्फ़ `news.approve` |
| प्रकाशित ख़बर चुपचाप बदलना | कारण ज़रूरी, हर वर्ज़न सुरक्षित, ऑडिट लॉग |
| मनगढ़ंत इमेज/मीडिया path | लाइब्रेरी में मौजूद होना ज़रूरी |
| ग़लत श्रेणी/लोकेशन/टैग ID | मौजूद होने की जाँच; टैग नाम से, अधिकतम 15 |
| एक साथ दो लोग बदलें | फ़ॉर्म में `updated_at`; बीच में किसी और ने सेव किया हो तो चेतावनी, ओवरराइट नहीं |
| CSRF / बड़ी POST | हर फ़ॉर्म/AJAX पर टोकन; लेख की लंबाई सीमा |

## 7. टेस्ट के नतीजे (सब पास)

| जाँच | नतीजा |
|---|---|
| अपडेट / नया इंस्टॉल | Phase 3 वाली साइट पर एक क्लिक में migration 000004; नए prefix पर चारों migration, दोबारा चलाने पर कुछ नहीं दोहराया |
| रिपोर्टर | ड्राफ़्ट बना (हिंदी शीर्षक से अंग्रेज़ी स्लग, `<script>`/`onclick` हटे, टैग/टॉपिक/गैलरी/लोकेशन जुड़े, वर्ज़न v1); फ़्लैग भेजने पर भी नहीं लगा; प्रकाशित करने की कोशिश मना; भेजने के बाद बदलना 403 और एडिट पेज हिस्ट्री पर; दूसरे रिपोर्टर को यह ख़बर हर रास्ते (edit/history/preview/transition/सूची) पर 404 |
| डेस्क | बिना कारण अस्वीकार मना; अस्वीकार का कारण रिपोर्टर को दिखा, आंतरिक टिप्पणी नहीं; रिपोर्टर ने सुधार कर "सेव करके भेजें"; समीक्षा → फ़ैक्ट चेक → मंज़ूर → प्रकाशित; बिना श्रेणी या 20 शब्द से कम पर प्रकाशन मना |
| वर्ज़न | पुराने `updated_at` वाले फ़ॉर्म से सेव मना (ओवरराइट नहीं); प्रकाशित ख़बर बिना कारण नहीं बदली; कारण + सुधार सूचना सेव; तुलना में `12 → 15` शब्द-स्तर पर; v1 वापस लाने पर नया v4 बना |
| शेड्यूल | अतीत का समय मना; भविष्य का समय सेव; समय आने पर अगले अनुरोध में अपने आप प्रकाशित और टिप्पणी दर्ज |
| टैग गिनती | सिर्फ़ प्रकाशित ख़बरें गिनी जाती हैं; हटाने/ट्रैश पर दोबारा गिनती |
| असाइनमेंट | ग़ैर-रिपोर्टर को सौंपना मना; रिपोर्टर को आगे/देर टैब सही; रिपोर्टर "पूरा" ख़ुद नहीं चुन सकता; "लिखना शुरू करें" से जुड़ी ख़बर; भेजने पर असाइनमेंट "ख़बर भेजी", प्रकाशन पर "पूरा" |
| बल्क / ट्रैश | रिपोर्टर का बल्क प्रकाशन हर ख़बर पर मना और संदेश में ID; रिपोर्टर प्रकाशित ख़बर ट्रैश नहीं कर सकता; ट्रैश किए बिना स्थायी delete मना; delete पर हिस्ट्री भी हटी |
| होमपेज बिल्डर | "हाथ से चुनें" में ख़बर खोजकर क्रम से जोड़ना; सब हटाने पर ख़ाली सूची सेव |
| CSRF / UI | बिना टोकन 419; Playwright: टैग चिप्स, लोकेशन खोज, गैलरी/इमेज पिकर, संबंधित ख़बर, शब्द गिनती, सेव → भेजें, डेस्क, हिस्ट्री, diff, प्रीव्यू, मोबाइल; कोई JavaScript त्रुटि नहीं |

- ब्रेकिंग फ़्लैग अभी सिर्फ़ ख़बर पर निशान है; टिकर/अलर्ट Phase 7 (ब्रेकिंग कंट्रोल रूम) में।
