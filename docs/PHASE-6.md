# Phase 6: रिपोर्टर भर्ती, आवेदन, रिपोर्टर पोर्टल, सत्यापन, ID कार्ड, पत्र, ब्यूरो

## 1. लक्ष्य

- **रिपोर्टर बनें (§22)** `/join-as-reporter`: कई चरणों वाला फ़ॉर्म (व्यक्तिगत, पता, पेशेवर, दस्तावेज़, घोषणा)। आवेदन संख्या `RPT-APP-2026-000001`। दस्तावेज़ सार्वजनिक फ़ोल्डर में नहीं, `storage/private` में।
- **आवेदन प्रबंधन (§23)**: सूची (स्थिति टैब, ज़िला/प्रकार/खोज), पूरा विवरण, दस्तावेज़ देखना/डाउनलोड, आंतरिक टिप्पणी, जाँच किसी को सौंपना, सुधार माँगना (आवेदक को दिखे), मंज़ूर, अस्वीकार, होल्ड। स्थितियाँ: नया, समीक्षा में, दस्तावेज़ बाकी, सत्यापन बाकी, मंज़ूर, अस्वीकार, होल्ड।
- **आवेदन की स्थिति (§24)** `/application-status`: आवेदन संख्या + मोबाइल → OTP (आवेदक के ईमेल पर; SMS/WhatsApp गेटवे Phase 11 के नोटिफ़िकेशन सेंटर में) → सिर्फ़ सुरक्षित जानकारी।
- **रिपोर्टर प्रबंधन (§25)**: मंज़ूरी पर यूज़र खाता (Reporter रोल) + रिपोर्टर ID `RPT-2026-0001`, पद, बीट, क्षेत्र, ज़िला, ब्यूरो, जॉइनिंग और वैधता। प्रोफ़ाइल: KYC दस्तावेज़, ख़बरें, असाइनमेंट, प्रदर्शन, लॉगिन हिस्ट्री, जारी दस्तावेज़; नवीनीकरण, निलंबन, दोबारा चालू, इस्तीफ़ा।
- **रिपोर्टर पोर्टल (§26)**: एडमिन पैनल में "मेरा रिपोर्टर प्रोफ़ाइल": प्रोफ़ाइल, प्रदर्शन (प्रकाशित/अस्वीकार/व्यूज़), अपना ID कार्ड और पत्र डाउनलोड। ख़बर, ड्राफ़्ट, मीडिया, असाइनमेंट, संपादक की टिप्पणी Phase 4 से पहले ही हैं।
- **ID कार्ड और पत्र (§27)**: ID कार्ड (QR के साथ), अधिकार पत्र, नियुक्ति पत्र, प्रेस प्रमाणपत्र, अनुभव प्रमाणपत्र। हर दस्तावेज़ का नंबर और रिकॉर्ड; प्रिंट/PDF के लायक पेज (ब्राउज़र से "PDF में सेव")। हस्ताक्षर, मुहर, हस्ताक्षरकर्ता सेटिंग से।
- **सार्वजनिक सत्यापन (§28)** `/verify-reporter`: रिपोर्टर ID + मोबाइल, या ID कार्ड का QR। सिर्फ़ सुरक्षित जानकारी (फ़ोटो, नाम, ID, पद, ज़िला, राज्य, जॉइनिंग, वैधता, स्थिति); मोबाइल छिपा।
- **ब्यूरो (§29)**: मुख्यालय, राज्य, ज़िला, तहसील/शहर ब्यूरो; ब्यूरो प्रमुख; रिपोर्टर ब्यूरो में; ब्यूरो-वार रिपोर्ट (रिपोर्टर, इस महीने की ख़बरें, व्यूज़)।

## 3. रूट

| पता | काम | अनुमति |
|---|---|---|
| `/join-as-reporter` (GET/POST) | आवेदन | सार्वजनिक (CSRF, रेट लिमिट, honeypot) |
| `/application-status` (+ OTP) | स्थिति | सार्वजनिक (OTP, रेट लिमिट) |
| `/verify-reporter`, `/verify-reporter/{code}/{token}` | सत्यापन | सार्वजनिक (रेट लिमिट) |
| `/admin/applications…` | आवेदन | applications.view/edit/approve/delete/export |
| `/admin/reporters…` | रिपोर्टर, दस्तावेज़, नवीनीकरण, निलंबन | reporters.* |
| `/admin/bureaus…` | ब्यूरो | bureaus.* |
| `/admin/my-reporter-profile` | रिपोर्टर पोर्टल | रिपोर्टर प्रोफ़ाइल वाला यूज़र |

## 4. कोड

- **Controllers**: `Front\ReporterJoinController` (जॉइन + स्थिति), `Front\VerifyController`; `Admin\ApplicationController`, `Admin\ReporterController` (दस्तावेज़ जारी/रद्द/प्रिंट भी), `Admin\BureauController`, `Admin\ReporterPortalController`
- **Models**: `Bureau`, `ReporterApplication`, `Reporter`, `ReporterDocument`
- **Services**: `ReporterService` (नंबर, मंज़ूरी → खाता, नवीनीकरण, स्थिति), `PrivateFileService` (निजी अपलोड/डाउनलोड), `OtpService`; QR टोकन `ReporterService::token()` (HMAC), दस्तावेज़ का पाठ `app/Views/print/reporter-document.php`
- **JS**: फ़ॉर्म के चरण (बिना JS भी पूरा फ़ॉर्म चलता है), QR (लोकल `qrcode-generator`, MIT)

## 5. अनुमतियाँ

- `applications.view` सूची/विवरण/दस्तावेज़, `applications.edit` टिप्पणी/स्थिति/सौंपना/सुधार माँगना, `applications.approve` मंज़ूर (रिपोर्टर खाता बनता है), `applications.delete`, `applications.export`
- `reporters.view/create/edit/delete`, `reporters.approve` दस्तावेज़ जारी/रद्द करना, `reporters.manage` निलंबन/इस्तीफ़ा/नवीनीकरण, `reporters.export`
- `bureaus.*`
- रिपोर्टर सिर्फ़ अपना प्रोफ़ाइल और अपने दस्तावेज़ देख सकता है

## 6. सुरक्षा

| जोखिम | उपाय |
|---|---|
| पहचान पत्र जैसे दस्तावेज़ लीक होना | `storage/private` (वेब से पहुँच नहीं), सिर्फ़ अनुमति वाले एडमिन का डाउनलोड रूट, ऑडिट लॉग |
| नकली/ख़तरनाक फ़ाइल | finfo MIME (JPG/PNG/PDF), आकार सीमा, रैंडम नाम |
| स्पैम आवेदन | CSRF, IP रेट लिमिट, honeypot, एक मोबाइल से एक खुला आवेदन |
| स्थिति पेज से जानकारी चोरी | आवेदन संख्या + मोबाइल + OTP; OTP hashed, 10 मिनट, 5 कोशिश; सिर्फ़ स्थिति और सुरक्षित संदेश |
| सत्यापन पेज से निजी डेटा | ID + मोबाइल दोनों या QR का HMAC टोकन; मोबाइल/पता/जन्मतिथि कभी नहीं; रेट लिमिट |
| नकली ID कार्ड | QR में हस्ताक्षरित (HMAC) टोकन; निलंबित/समाप्त/रद्द कार्ड पर सत्यापन साफ़ "मान्य नहीं" |
| दूसरे रिपोर्टर का प्रोफ़ाइल | पोर्टल सिर्फ़ अपना; एडमिन रूट पर अनुमति |

## 7. जाँच के नतीजे

| जाँच | नतीजा |
|---|---|
| जॉइन फ़ॉर्म: honeypot, 15 सेकंड से जल्दी जमा, ग़लत ज़िला, हस्ताक्षर गायब, PHP कोड वाली नकली `.pdf`, दोहराया मोबाइल | सब रुके, हिंदी संदेश फ़ील्ड के नीचे |
| सही आवेदन | `RPT-APP-2026-000002`, फ़ाइलें `storage/private` में (0640), वेब से सीधा खोलने पर 403 |
| रेट लिमिट | 5 आवेदन/घंटा प्रति IP के बाद 429 |
| स्थिति पेज | ग़लत मोबाइल → सामान्य संदेश; ग़लत OTP → "कोड सही नहीं"; सही OTP → स्थिति + आवेदक को दिखने वाला संदेश |
| एडमिन: दस्तावेज़ बाकी (संदेश सहित), जाँच सौंपना, दस्तावेज़ देखना/डाउनलोड | काम करता है; हर दस्तावेज़ देखने का ऑडिट लॉग; डाउनलोड पर `nosniff` + CSP sandbox |
| मंज़ूरी | यूज़र (Reporter रोल) + `RPT-2026-0001` + फ़ोटो सार्वजनिक कॉपी; पासवर्ड लिंक से पासवर्ड बना, लॉगिन हुआ |
| दस्तावेज़ | 5 प्रकार जारी; नया ID कार्ड पुराने को रद्द करता है; ग़लत प्रकार 422; प्रिंट पेज पर QR |
| सत्यापन | QR सही → "सत्यापित"; टोकन बदला → "QR मान्य नहीं"; ID+मोबाइल सही/ग़लत; निलंबित → "अभी मान्य नहीं", लॉगिन बंद, कार्ड/पत्र रद्द |
| दोबारा सक्रिय + नवीनीकरण | वैधता 12 महीने बढ़ी, लॉगिन खुला |
| ब्यूरो | बनाना, ख़ुद/नीचे वाले के नीचे रखना रुका, नीचे ब्यूरो/रिपोर्टर हों तो हटाना रुका |
| RBAC | संपादक: आवेदन/रिपोर्टर देख सकता है; मंज़ूरी, एक्सपोर्ट, संपादन, दस्तावेज़ जारी, नवीनीकरण, ब्यूरो → 403 |
| पोर्टल | रिपोर्टर सिर्फ़ अपने दस्तावेज़ (दूसरे का 404); एडमिन रिपोर्टर/आवेदन पेज 403 |
| CSRF | ग़लत टोकन → 419 |
| मोबाइल (390px) | जॉइन, सत्यापन, पोर्टल; क्षैतिज स्क्रॉल नहीं; JS त्रुटि नहीं |
| नया इंस्टॉल | 6 माइग्रेशन, मुख्यालय ब्यूरो, फ़ुटर लिंक; दोबारा चलाने पर कुछ नहीं बदला |

**इस चरण में मिली पुरानी गड़बड़ी:** राउटर `{token:[a-f0-9]{64}}` जैसे quantifier वाले पैरामीटर नहीं समझता था, इसलिए "पासवर्ड भूल गए" का रीसेट लिंक (Phase 1 से) ग़लत बनता था। राउटर ठीक किया: अब regex में `{4}` / `{2,8}` चलते हैं।
