# Phase 12: फ़ॉर्म बिल्डर, न्यूज़ टिप, शिकायत/ग्रीवेंस, संपर्क, करियर/इंटर्नशिप

## 1. लक्ष्य

**एक इंजन, कई काम।** सारे सार्वजनिक फ़ॉर्म एक ही "फ़ॉर्म बिल्डर" से बनते हैं; हर जमा फ़ॉर्म (submission) एक ही इनबॉक्स ढाँचे में आता है। फ़ॉर्म का **प्रकार** तय करता है कि वह किस मॉड्यूल में दिखेगा, किसकी अनुमति से, और उसकी स्थितियाँ क्या होंगी।

| प्रकार | कहाँ दिखता है | स्थितियाँ | अनुमति |
|---|---|---|---|
| संपर्क / विज्ञापन पूछताछ / फ़ीडबैक / कस्टम | संपर्क इनबॉक्स (§53) | नया, प्रगति में, जवाब दिया, बंद, स्पैम | `contacts.*` (कस्टम: `forms.*`) |
| न्यूज़ टिप (§31) | न्यूज़ टिप | नया, जाँच में, असाइनमेंट/ड्राफ़्ट बना, अस्वीकृत, स्पैम | `news_tips.*` |
| शिकायत / ग्रीवेंस (§54) | शिकायतें | नई, प्रगति में, निपटाई, अस्वीकृत, बंद | `complaints.*` |
| नौकरी आवेदन (§55) | करियर → आवेदन | नया, शॉर्टलिस्ट, इंटरव्यू, चयनित, अस्वीकृत | `careers.*` |

**फ़ॉर्म बिल्डर (§52)** — बिना कोडिंग के फ़ॉर्म: शीर्षक, विवरण, सफलता संदेश, बटन का नाम, सूचना ईमेल, स्थिति। खाने: टेक्स्ट, ईमेल, मोबाइल, नंबर, URL, बड़ा टेक्स्ट, ड्रॉपडाउन, रेडियो, चेकबॉक्स, तारीख़, फ़ाइल (प्रकार और MB सीमा), सहमति, शीर्षक-लाइन। हर खाने का लेबल, ज़रूरी/वैकल्पिक, मदद टेक्स्ट, विकल्प, चौड़ाई, क्रम (ऊपर/नीचे)। फ़ॉर्म `/form/{slug}` पर, या किसी पेज/ख़बर में `[form:slug]`।

पहले से बने (सिस्टम) फ़ॉर्म: **संपर्क करें**, **हमें ख़बर भेजें**, **शिकायत दर्ज करें**, **नौकरी/इंटर्नशिप आवेदन**, **विज्ञापन के लिए संपर्क**, **फ़ीडबैक**। इनके खाने बदल सकते हैं; प्रकार और key नहीं।

**हर जमा फ़ॉर्म पर:** संदर्भ नंबर (जैसे `TIP-2026-00012`, `CMP-2026-00003`), तारीख़, पेज, IP का हैश, ब्राउज़र; फ़ाइलें `storage/private` में (वेब से सीधे नहीं खुलतीं); भेजने वाले को पावती ईमेल; स्टाफ़ को घंटी/ईमेल सूचना (Phase 11 नोटिफ़िकेशन सेंटर से)।

**इनबॉक्स (एडमिन):** स्थिति के टैब, खोज, किसे सौंपा, अंदरूनी नोट्स (टाइमलाइन), ईमेल से जवाब (और "जवाब दिया" स्थिति), स्पैम, CSV एक्सपोर्ट, फ़ाइल देखें/डाउनलोड (अनुमति से)।

**न्यूज़ टिप (§31):** सार्वजनिक पेज `/send-news` ("हमें ख़बर भेजें"): नाम, मोबाइल, लोकेशन, विवरण, फ़ोटो, वीडियो, दस्तावेज़, सहमति। एडमिन: जाँचें, अस्वीकार, **असाइनमेंट बनाएँ** (रिपोर्टर को), **ड्राफ़्ट ख़बर बनाएँ** (विवरण + स्रोत "पाठक द्वारा भेजी गई")।

**शिकायत/ग्रीवेंस (§54):** शिकायत नंबर, आवेदक, संपर्क, ख़बर का URL, शिकायत का प्रकार, विवरण, सबूत, **सौंपा गया अधिकारी**, **जवाब** (शिकायतकर्ता को दिखता है), स्थिति, **निपटारा**। **सार्वजनिक ट्रैकिंग** `/complaint/track`: शिकायत नंबर + रजिस्टर्ड मोबाइल/ईमेल से स्थिति और जवाब (सेटिंग से चालू/बंद)।

**करियर/इंटर्नशिप (§55):** वैकेंसी: पद, विभाग, जगह, प्रकार (फ़ुल-टाइम/पार्ट-टाइम/इंटर्नशिप/फ़्रीलांस), विवरण, योग्यता, पद संख्या, अंतिम तारीख़, स्थिति। सार्वजनिक `/careers` और `/careers/{slug}` पर आवेदन (CV: PDF/DOC/DOCX)। अंतिम तारीख़ निकलने पर आवेदन अपने आप बंद। Google के लिए `JobPosting` स्कीमा।

**स्पैम से बचाव:** honeypot, फ़ॉर्म भरने का कम से कम समय, throttle (एक IP से सीमित), फ़ाइल का असली प्रकार जाँच (नाम नहीं), इमेज दोबारा जाँच, सहमति ज़रूरी।

## 2. डेटाबेस (migration `000012`)

| टेबल | मुख्य कॉलम |
|---|---|
| `forms` | title, slug, type, description, success_message, submit_label, notify_emails, status, is_system, settings |
| `form_fields` | form_id, field_key, label, type, options, required, help, placeholder, width, accept, max_mb, sort_order |
| `form_submissions` | form_id, ref_no, status, data (JSON), files (JSON), name, email, mobile, job_id, assigned_to, response, resolution, ip_hash, user_agent, page_url |
| `form_notes` | submission_id, user_id, type (note/reply/status/system), body |
| `jobs` | title, slug, department, location, job_type, description, requirements, vacancies, deadline, status |

## 3. रूट

| पता | काम |
|---|---|
| `/form/{slug}` (GET/POST), `/form/{slug}/done` | कोई भी फ़ॉर्म |
| `/send-news`, `/complaint`, `/contact-form` | सिस्टम फ़ॉर्म के छोटे पते |
| `/complaint/track` | शिकायत की स्थिति |
| `/careers`, `/careers/{slug}` | नौकरियाँ, आवेदन |
| `/admin/forms…` | फ़ॉर्म बिल्डर (`forms.*`) |
| `/admin/inbox/{type}`, `/admin/submissions/{id}` | इनबॉक्स (प्रकार के हिसाब से अनुमति) |
| `/admin/careers…` | वैकेंसी और आवेदन (`careers.*`) |

## 4. सुरक्षा

| जोखिम | उपाय |
|---|---|
| फ़ाइल से हमला | असली MIME जाँच (finfo), तय प्रकार और आकार, बेतरतीब नाम, `storage/private` में, सिर्फ़ अनुमति वाले रूट से; इमेज की दोबारा जाँच |
| XSS | हर मान सादा टेक्स्ट के रूप में सेव/दिखाया; फ़ॉर्म का HTML एडमिन भी नहीं डाल सकता (सिर्फ़ विवरण में साफ़ किया HTML) |
| स्पैम/बॉट | honeypot, समय जाँच, throttle, सहमति |
| ट्रैकिंग से जानकारी लीक | नंबर + रजिस्टर्ड मोबाइल/ईमेल दोनों ज़रूरी, throttle, सिर्फ़ स्थिति और सार्वजनिक जवाब |
| गलत व्यक्ति को जानकारी | इनबॉक्स प्रकार के हिसाब से अनुमति; फ़ाइलें भी उसी अनुमति से |
| CSRF | सारे POST पर CSRF |

## 5. जाँच के नतीजे

| जाँच | नतीजा |
|---|---|
| PHP/JS सिंटैक्स | सारी नई/बदली फ़ाइलें `php -l` पास; admin.js पार्स ठीक |
| माइग्रेशन | मौजूदा साइट पर 000012 चला; नया इंस्टॉल (12 माइग्रेशन): 6 सिस्टम फ़ॉर्म (44 खाने), फ़ुटर में 3 लिंक, संपर्क पेज में `[form:contact]` |
| संपर्क फ़ॉर्म | 3 सेकंड से पहले भेजा → रुका; ग़लत ईमेल/मोबाइल/विकल्प/सहमति → 4 हिंदी त्रुटियाँ; सही → `CT-2026-00001`, पावती पेज |
| न्यूज़ टिप | PHP फ़ाइल को `.jpg` नाम → रुकी; फ़ोटो + PDF `storage/private` में; "पहचान गोपनीय" चुना तो असाइनमेंट के स्रोत में नाम/नंबर नहीं; टिप → असाइनमेंट (रिपोर्टर को सूचना), स्थिति "बना" |
| शिकायत | `CMP-…` नंबर; ग़लत मोबाइल से ट्रैकिंग नहीं; "+91 91234 56780" जैसे लिखा सही नंबर पहचाना; अधिकारी सौंपा, जवाब + निपटारा → ट्रैकिंग पर दिखे |
| करियर | खुली वैकेंसी सूची में; तारीख़ निकली → छुपी, पेज पर "आवेदन बंद", noindex; DOCX CV (zip के अंदर जाँच) के साथ आवेदन; बंद वैकेंसी पर आवेदन रुका; JobPosting स्कीमा; विवरण से `<script>` हटी |
| फ़ॉर्म बिल्डर | एक विकल्प वाला रेडियो रुका; हिंदी लेबल से key अपने आप; खाना जोड़ें/ऊपर/हटाएँ → सेव पर वही क्रम; सिस्टम फ़ॉर्म हटाना रुका |
| इनबॉक्स | ईमेल से जवाब (नोट में दर्ज), अंदरूनी नोट, CSV, फ़ाइल सिर्फ़ अनुमति से (हर बार ऑडिट) |
| सूचनाएँ | हर नया फ़ॉर्म उसी इनबॉक्स की अनुमति वालों को (Editor को टिप, संपर्क नहीं) |
| अनुमति | Editor: सिर्फ़ न्यूज़ टिप (और उसकी फ़ाइलें); शिकायत/संपर्क/करियर/फ़ॉर्म 403; Reporter: सब 403 |
| CSRF / फ़ाइल | 8 POST रूट बिना टोकन → 419; निजी फ़ाइल सीधे URL से → 403 |
| मोबाइल (390px) | 10 वेबसाइट + 11 एडमिन पेज, कोई साइडवेज़ स्क्रोल नहीं; JS त्रुटि नहीं |

जाँच में ठीक किया: view के अंदर फ़ॉर्म render करने से पेज का लेआउट (हेडर/फ़ुटर) हट रहा था, अब फ़ॉर्म controller में बनता है; शिकायतकर्ता को ईमेल न जाने पर भी "भेजा" लिखा जा रहा था; `data-confirm-then` (जैसे न्यूज़लेटर "अभी भेजें") अब पूरे एडमिन में पुष्टि पूछता है।

**कर्मचारी (HR) मॉड्यूल** master prompt के किसी phase की सूची में नहीं है, इसलिए अभी छुपा है।
